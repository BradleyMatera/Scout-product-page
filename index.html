03 / Scope

Current application scope vs. planned generalization.

The runtime knowledge in the current codebase scopes Scout to Bradley Matera's professional information and Scout's own runtime. A customer-neutral, no-KB mode is not the current shipped application.

Current application

ProjectHub Recruiter Alpha

The deployed application is a recruiter/portfolio assistant with bundled knowledge and recruiter-specific evidence tools.

  • Projects, skills, work history, education, certifications, career goals, and public contact information
  • Project comparison, skill evidence, profile retrieval, and role matching
  • Conversation state and referent handling
  • Questions about Scout's own runtime and architecture
  • Cloudflare generation with local retrieval and validation
scope facts ↗tool catalog ↗
Not implemented as a product mode

Customer-neutral Scout Core

The current productization direction is to separate tenant-specific data and tool assumptions from reusable retrieval, state, inference, validation, and orchestration code.

  • Supported empty/no-knowledge baseline mode
  • Tenant-neutral identity and knowledge contracts
  • Generalized tool and workflow extension interfaces
  • Cross-domain test suites using unrelated domains
  • Deployment/config validation and buyer/operator documentation

Historical scorer correction

On August 19, stored live outputs were initially summarized as 114/115 plus a 40/40 focused run under the older scorer. A later raw-output audit identified semantic false positives, including closed-world employment denials, incorrect future-capability polarity, incorrect contract states, and project/technology provenance errors.

Commit e013a320 added a stricter semantic scorer and recorded an offline rescore baseline of 131/178 (73.6%) for the preserved pre-strict artifacts. Later engine changes mean that number is historical; it is not a claim about the current production release.

Historical evaluation results stay labeled with the scorer and runtime they came from. Current quality should be measured by rerunning the current harness against the current target rather than reusing an older percentage.

09 / Current limits

Boundaries supported by the current repository state.

These are implementation or deployment limits, not positioning language.

Current Scout is recruiter-specific.

The runtime knowledge scopes the deployed application to Bradley Matera's professional information and Scout's own runtime.

No-KB operation is not a supported shipped mode.

Current CI and knowledge access paths assume recruiter knowledge structure. Empty operation requires explicit implementation and tests.

Browser/WebGPU inference is experimental.

The current production generation path uses Cloudflare Workers AI.

Ollama production fallback is gated.

Cloudflare-to-Ollama fallback requires explicit enablement and SCOUT_OLLAMA_QUALIFIED=true.

Production deployment still includes a legacy SCP path.

The repository contains Docker production-parity assets, while the release specification still identifies the current SCP-based GCP path as legacy and intended for replacement.

Historical metrics are runtime/scorer-specific.

Old qualification percentages should not be reused as current quality measurements after model, scorer, contract, or pipeline changes.
