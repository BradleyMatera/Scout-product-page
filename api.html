Scout / API

Current runtime interface.

The ProjectHub backend exposes a small Express API for chat, health, retrieval diagnostics, bounded learning/diagnostics, and operational telemetry. This page documents the checked-in interface; it is not a promise of a public multi-tenant commercial API or an SLA.

Checked-in ProjectHub routes.

The route names below are documented in the repository and implemented in server-gemini.js. Diagnostic and telemetry routes are operational interfaces, not customer-facing product guarantees.

02 / Chat request

Minimal request shape.

The frontend sends a message, per-tab session identifier, and recent conversation history. Server-side logic sanitizes and bounds the history before it is used.

{
  "message": "Which project best demonstrates debugging?",
  "sessionId": "per-tab-id",
  "history": [
    {
      "user": "What is Bradley strongest at?",
      "assistant": "..."
    }
  ]
}
03 / Response metadata

The reply is not the only output.

Current runtime telemetry can expose where the prose came from, which model/provider was used, model-call counts, token/neuron estimates, latency, repair attempts, retrieval counts, and session-level usage when available.

Source

MODEL_GENERATION

A model authored the visible answer from retrieved evidence and the output passed the runtime validation path.

Source

DIRECT_KB

Verified knowledge supplied the visible answer without requiring a generative model call.

Source

TECHNICAL_ERROR

Generation or factual validation failed closed rather than silently accepting unsupported output.

04 / Current limits

What this API page does not claim.

The checked-in ProjectHub API is a real runtime interface, but the commercial Scout API surface is still part of productization work.

No public SLA

Project runtime, not a published platform contract.

Endpoint names and payloads can evolve with ProjectHub. This page documents the repository state rather than promising backwards compatibility to external integrators.

No API-key product

No self-serve developer account system is claimed.

The current product page does not advertise customer API keys, metered developer accounts, or a public API billing system.

Docs drift

Older API prose can describe the local-Ollama phase.

The repository API guide still contains text from the earlier local-only configuration. Current runtime facts identify Cloudflare Workers AI as normal generation, so this page does not repeat the superseded model claim.

For implementation verification, inspect server-gemini.js and data/scout-runtime-knowledge.json together. The API guide is useful for route names and payload shape but contains older inference-provider language.
